# 관리자 페이지 및 개발 방안

이 문서는 현재 확정된 PHP·MariaDB 기반 멀티 교회 플랫폼의 교회 관리자와 플랫폼 본사 관리자 화면, 권한, 처리 흐름, 개발 단계와 검수 기준을 정의한다.

## 1. 개발 원칙

- 공통 기반을 먼저 만들고 기능별로 `관리자 입력 → 사용자 화면 출력 → 권한·통계 검증` 순서로 완성한다.
- 현재 1순위는 전도지·초대장 전용 서비스이며 교회 홈페이지는 초대장 MVP 안정화 이후 개발한다.
- 모든 업무 데이터는 `church_id`로 격리한다.
- 체험 계정은 체험 서버 공용 DB, 유료 계정은 배정된 유료 서버의 교회별 DB를 사용한다.
- 관리 화면은 PC 중심 반응형으로 만들되 태블릿과 모바일에서도 긴급 수정이 가능해야 한다.
- 영상 파일은 업로드하지 않고 YouTube 링크만 등록한다.
- 이미지 원본은 최대 1MB, 초대장 이미지는 500KB를 권장하고 WebP·썸네일을 자동 생성한다.
- 삭제는 즉시 영구 삭제보다 휴지통·복구·감사 기록을 우선한다.
- 구독 한도와 기능 권한은 화면 숨김만이 아니라 서버에서도 검사한다.

## 2. 관리자 영역 구분

### 교회 관리자

주소 예시: `https://교회도메인/admin` 또는 `https://admin.서비스도메인/church/{churchId}`

- 해당 교회의 홈페이지·게시판·회원·파일·초대장·통계·구독만 관리한다.
- 다른 교회의 ID를 URL에 입력해도 접근할 수 없어야 한다.
- 대표 관리자, 일반 관리자, 콘텐츠 담당자 역할을 구분한다.

### 플랫폼 본사 관리자

주소 예시: `https://control.서비스도메인`

- 교회·구독·서버·트래픽·장애·배포·고객지원을 통합 관리한다.
- 일반 교회 관리자와 로그인 경로·세션·권한을 분리한다.
- MFA를 필수로 하고 중요한 작업은 사유와 감사 로그를 남긴다.

## 3. 교회 관리자 공통 화면

### 공통 레이아웃

- 상단: 교회 선택 정보, 홈페이지 보기, 알림, 계정 메뉴
- 왼쪽 메뉴: 대시보드부터 고객지원까지
- 본문: 페이지 제목, 도움말, 주요 작업 버튼, 필터, 목록 또는 편집 폼
- 하단 또는 고정 영역: 저장, 미리보기, 게시, 취소
- 모바일: 왼쪽 메뉴를 접이식 메뉴로 전환

### 공통 기능

- 검색·필터·정렬·페이지 이동
- 임시저장·게시·예약 게시
- 저장 전 유효성 검사
- 변경사항이 있을 때 이탈 경고
- 작업 성공·실패 메시지
- 권한 없는 버튼 비노출 및 서버 접근 차단
- 최근 작업 이력과 휴지통 복구

- 오늘 방문자·페이지뷰

- 구독 상태: 체험·정상·미납·정지, 다음 결제일

#### 주요 기능

- 홈페이지 바로가기와 새 창 미리보기
- 자주 사용하는 게시글·초대장 생성 바로가기
- 트래픽 증액·요금제 변경 요청

## 7. 기술 구성

### 백엔드

- PHP 8.x
- MariaDB
- MVC 또는 계층형 구조: Controller, Service, Repository
- 세션 기반 관리자 인증
- 비밀번호 `password_hash`/`password_verify`
- CSRF, 입력 검증, 출력 이스케이프
- 작업 큐: 이미지 변환, 통계 집계, 데이터 이전, 알림

### 프론트엔드

- 1차: PHP 템플릿 + HTML·CSS·JavaScript
- 관리자 표·필터·모달 등 필요한 부분만 경량 JavaScript 사용
- React는 복잡한 페이지 빌더나 실시간 대시보드가 필요해질 때 도입
- 모바일 우선 사용자 홈페이지와 PC 중심 반응형 관리자

### 저장소

- 파일 본문은 파일시스템 또는 객체 저장소
- DB에는 경로·크기·해시·MIME·`church_id`·연결 대상
- 이미지 변환본을 `media_variants`로 관리
- YouTube는 URL·영상 ID·썸네일 정보만 저장

### 비동기 작업

- 이미지 변환
- 일·월 트래픽 집계
- 저장공간 재계산
- 체험 만료 알림
- 유료 DB 이전
- 백업과 오래된 휴지통 정리

초기에는 cron과 DB 작업 큐로 시작하고 규모가 커지면 Redis 등 전용 큐를 검토한다.

## 9. 단계별 개발 계획

### 0단계: 프로젝트 기반

- 환경설정, DB 마이그레이션, 라우팅, 오류 처리
- 공통 레이아웃·로그·테스트 구조
- 개발·운영 환경 분리

완료 기준: 새 환경에서 설치 명령으로 앱과 DB가 정상 실행된다.

### 1단계: 인증·교회 격리·상품 기반

- 플랫폼·교회 관리자 로그인
- 교회·단체 생성, 역할·권한, `church_id` 격리
- `product_family`, 기능 권한, 30일 체험 구독
- 관리자 감사 로그

완료 기준: 다른 교회 URL·ID로 데이터 접근이 불가능하고 초대장 전용 상품 권한만 정확히 적용된다.

### 2단계: 초대장 전용 관리자

- 전용 대시보드와 교회·단체 최소 기본정보
- 초대장 목록·생성·수정·복제·미리보기·게시·종료
- 행사 유형과 세로형·정사각형·가로형 템플릿
- 이미지·YouTube·지도·연락처·공개·비밀번호·만료

완료 기준: 홈페이지 없이 관리자가 여러 초대장을 만들고 모바일 공개 주소로 게시할 수 있다.

### 3단계: 신청·공유·통계

- 참석 신청서와 개인정보 동의
- 신청자 검색·승인·취소·CSV 내보내기
- 공유 이미지·링크·QR 코드
- 조회·공유·신청 전환 통계

완료 기준: 모바일 신청 흐름과 관리자 신청자 관리가 동작하고 교회별 통계가 분리된다.

### 4단계: 이미지·트래픽·구독

- 500KB 권장 검증, WebP·썸네일·지연 로딩
- 저장공간과 일·월 트래픽 집계
- 초대장 수·사진 수·신청자 수 한도
- 70%·85%·100% 알림과 제한
- 30일 체험 만료, 기본형·성장형 전환

완료 기준: 구독 한도가 서버에서 강제되고 테스트 사용량과 초기화 기록이 정확하다.

### 5단계: 플랫폼 운영·백업

- 체험·초대장 구독·고객지원 통합 관리
- 서버 상태·임계치·헬스체크
- DB·업로드 파일 매일 백업, 최근 7일 순환 보관
- 복원 검사와 백업 실패 알림

완료 기준: 체험 생성·만료·유료 전환과 7일 백업 복원 절차가 검증된다.

### 6단계: 교회 홈페이지

- 교회정보·로고·예배·오시는 길
- 템플릿 2종과 사용자 홈·소개·예배·지도
- 메뉴·페이지·게시판·YouTube 설교
- 초대장 전용 고객의 홈페이지 상품 전환

완료 기준: 기존 초대장·사진·신청자 데이터를 유지하면서 홈페이지 기능을 활성화할 수 있다.

### 7단계: 유료 서버 배치

- 서버·교회·체험·구독 통합 관리
- 체험에서 유료 서버로 DB·파일 이전
- 서버당 20개 배치와 임계치 알림

완료 기준: 읽기 전용 전환, 이전, 무결성 확인과 롤백 절차를 시험한다.

### 8단계: 자동 설치·배포

- 신규 카페24 서버 설치 스크립트
- PHP·MariaDB·웹서버·SSL·방화벽·모니터링
- 앱 배포·마이그레이션·헬스체크·롤백

완료 기준: 빈 서버를 반복 가능한 절차로 등록하고 플랫폼에서 상태를 확인한다.

## 10. 1차 관리자 MVP

첫 번째 개발 목표는 전도지·초대장 전용 서비스로 제한한다.

1. 플랫폼 관리자 로그인
2. 교회·단체 생성과 관리자 로그인
3. `church_id` 격리와 초대장 전용 30일 체험
4. 초대장 전용 관리자 대시보드
5. 초대장 목록·생성·복제·게시·종료
6. 세로형·정사각형·가로형 모바일 템플릿
7. 이미지·YouTube·지도·연락처·공유·QR 코드
8. 참석 신청과 신청자 관리·CSV
9. 조회·공유·신청 통계
10. 트래픽·저장공간·구독 한도 카드
11. 체험 만료와 유료 전환
12. 매일 백업과 최근 7일 순환 보관

교회 홈페이지, 홈페이지 게시판·회원·설교와 고급 페이지 빌더는 초대장 MVP 안정화 후 개발한다. 결제 자동화, 문자·알림톡과 복잡한 실시간 통계도 후속 단계로 둔다.

## 12. 관리자 화면 진행상태 표시

플랫폼 관리자는 교회별 구축 상태를 볼 수 있어야 한다.

- 가입 완료
- 관리자 인증 완료
- 기본정보 입력
- 로고·디자인 설정
- 예배·오시는 길 입력
- 첫 게시물 등록
- 첫 설교 등록
- 초대장 생성
- 홈페이지 공개
- 개인 도메인 연결
- 유료 전환

각 항목을 퍼센트와 체크리스트로 표시하고, 교회 관리자 대시보드에도 `홈페이지 완성도`로 보여준다. 다음 작업 버튼을 제공해 관리자가 자연스럽게 구축을 완료하도록 안내한다.
