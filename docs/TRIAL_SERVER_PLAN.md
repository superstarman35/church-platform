# 30일 무료체험 서버 운영안

## 결정사항

- 개발·내부 테스트 단계에는 신규 호스팅을 추가하지 않는다.
- 실제 외부 교회 모집 직전에 16,000원형 리눅스 체험 전용 서버 1대를 추가한다.
- 무료체험 계정은 체험 서버의 공용 DB에서 `church_id`로 격리한다.
- 유료 전환 교회는 33,000원형 유료 교회 서버의 교회별 DB로 이전한다.
- 유료 교회 서버는 기본 20개 교회 단위로 운영한다.
- 모든 영상은 YouTube 링크 또는 임베드로만 제공한다.

## 서버 배치

```text
메인 서버 16,000원형
├─ 서비스 소개
├─ 회원가입·로그인
├─ 구독·결제 상태
├─ 교회·서버 배정
└─ 플랫폼 관리자

무료체험 서버 16,000원형
├─ 30일 체험 홈페이지
├─ 체험 공용 DB
├─ 체험 이미지·게시물
└─ 서비스 서브도메인

유료 교회 서버 33,000원형
├─ 유료 교회 1~20
├─ 교회별 DB
├─ 홈페이지·초대장
└─ 파일·통계·트래픽
```

## 단계별 도입

### 개발·내부 테스트

- 로컬 또는 메인 서버에서 테스트 교회 3~5개로 검증한다.
- 가입, 홈페이지 생성, 관리자 입력, 사용자 출력과 유료 전환 흐름을 개발한다.
- 실제 외부 모집 전까지 체험용 서버 비용을 발생시키지 않는다.

### 외부 무료체험 모집

- 체험 전용 서버를 추가하고 무료체험 계정만 배치한다.
- `교회아이디.서비스도메인` 형식의 서브도메인을 제공한다.
- 개인 도메인은 체험에서 제공하지 않는다.
- 기본 한도는 저장공간 300MB, 월 트래픽 2GB다.
- 이미지 최적화와 만료 데이터 정리를 적용한다.

## 초기 수용 기준

- 활성 무료체험 최대 30개부터 시작한다.
- CPU 70% 이상 지속, RAM 80% 이상, 디스크 70% 이상이면 증설을 검토한다.
- 트래픽뿐 아니라 DB 응답시간과 디스크 I/O도 확인한다.
- 실제 사용량이 안정적이면 활성 체험 수를 30개에서 50개 이상으로 단계적으로 높인다.
- 신규 수용 한도는 설정값으로 관리하여 운영자가 즉시 조정할 수 있게 한다.

## 유료 전환 절차

1. 결제 완료와 구독 상태를 확인한다.
2. 여유 있는 33,000원형 유료 교회 서버를 선택한다.
3. 대상 서버에 교회별 DB와 저장공간을 생성한다.
4. 체험 홈페이지를 잠시 읽기 전용으로 전환한다.
5. DB·이미지·파일을 이전하고 무결성을 검사한다.
6. 서비스 주소와 개인 도메인을 유료 서버에 연결한다.
7. 유료 구독 한도와 기능을 적용한다.
8. 정상 접속을 확인한 뒤 체험 데이터를 보관 기간 후 정리한다.

## 체험 종료

- 종료 7일 전부터 관리자에게 유료 전환을 알린다.
- 종료 후 7일 동안 결제·복구를 허용한다.
- 이후 방문자에게 종료 안내를 표시하고 관리자 데이터는 30일 동안 보관한다.
- 최종 삭제 전에 여러 차례 알리고 삭제 작업을 감사 로그에 기록한다.

## 보안·운영 원칙

- 메인 서버와 체험 서버를 분리해 무료 가입 급증이나 파일 공격의 영향을 격리한다.
- 업로드 확장자·MIME·크기 검사와 악성 파일 검사를 적용한다.
- 교회별 트래픽·용량 한도를 애플리케이션에서 강제한다.
- 체험 서버 장애가 플랫폼 관리자와 유료 홈페이지에 영향을 주지 않게 한다.
- 체험 서버의 데이터도 정기 백업하되 복구 보장 범위는 체험 약관에 명시한다.

## 상품 선택 주의

카페24 일반 홈페이지 제작형 호스팅은 독자적인 PHP·MariaDB 플랫폼 배치에 적합하지 않을 수 있다. 체험 서버는 PHP, MariaDB, 웹서버 설정과 배포 권한을 확보할 수 있는 리눅스 가상서버 상품을 사용한다.

## 향후 단일서버 구성

- 초기에는 카페24 리눅스 가상서버 기반의 메인·체험·유료 서버 분산 구성을 우선한다.
- 운영 규모와 비용에 따라 추후 하나의 단독 단일서버로 통합할 수 있다.
- 배포 구조는 서버 IP·경로·대수를 코드에 고정하지 않고 환경설정과 서버 레지스트리로 관리한다.
- 단일서버에서도 메인·체험·유료 서비스와 교회별 DB·파일·권한을 논리적으로 격리한다.
- 가상서버에서 단일서버로 DB·파일을 이전하고 검증·롤백할 수 있는 절차를 제공한다.
- 단일서버 장애가 전체 서비스 장애로 이어질 수 있으므로 일일 백업은 같은 물리 디스크 밖에도 보관한다.
